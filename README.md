# Учебный сайт на Laravel

Учебный проект по серверной веб-разработке. В лабораторной работе № 7 добавлены роли пользователей, разграничение доступа к новостям и комментариям с помощью Laravel Policies и Gate, а также создание и просмотр комментариев. Сохранены регистрация, сессионная аутентификация, защита маршрутов middleware `auth:sanctum` и CRUD новостей из предыдущих работ.

## Реализовано

- Регистрация и вход пользователей с проверкой введённых данных.
- Хеширование пароля и назначение роли «читатель» новым пользователям.
- Роли «читатель» и «модератор», связанные с пользователями через `role_id`.
- Policy для новостей: читатели просматривают публикации, а модераторы могут создавать, изменять и удалять их.
- Policy для комментариев: читатели добавляют и просматривают комментарии, модераторы могут также изменять и удалять их.
- Общее правило Gate `manage-articles` для управления новостями; модератор получает разрешение через `Gate::before`.
- Комментарии с привязкой к новости и автору.
- Проверка текста комментария через `CommentRequest`.
- Вложенные маршруты комментариев с проверкой принадлежности комментария указанной новости.
- Скрытие действий, недоступных пользователю, в Blade-шаблонах через `@can`.
- Защищённые маршруты новостей, комментариев, галереи и выхода под middleware `auth:sanctum`.
- CRUD новостей с пагинацией и проверкой данных через `ArticleRequest`.
- CSRF-защита state-changing форм.
- Сиды ролей, тестовых пользователей и новостей.

## Страницы и маршруты

| Адрес | Содержание |
| --- | --- |
| `/` | Главная страница со списком публикаций из `public/articles.json` |
| `/galery/{article}` | Публикация и полноразмерное изображение для авторизованного пользователя |
| `/register` | Форма регистрации |
| `/signin` | Альтернативный адрес формы регистрации |
| `/login` | Форма входа |
| `/logout` | Выход из системы методом `POST` |
| `/articles` | Новости из базы данных с пагинацией |
| `/articles/create` | Форма создания новости для модератора |
| `/articles/{article}` | Просмотр новости и комментариев |
| `/articles/{article}/edit` | Форма редактирования новости для модератора |
| `/articles/{article}/comments` | Добавление комментария |
| `/articles/{article}/comments/{comment}` | Изменение или удаление комментария |
| `/about` | Информация о проекте |
| `/contacts` | Контактные данные |

Маршруты новостей и комментариев доступны только после входа. Гости перенаправляются на `/login`. Для авторизованного пользователя действия дополнительно проверяются с учётом его роли. При отказе в доступе приложение возвращает HTTP 403 с сообщением о недостающих правах.

## Роли и разграничение доступа

Роли хранятся в таблице `roles`; у пользователя роль задаётся внешним ключом `users.role_id`.

| Роль | Возможности |
| --- | --- |
| Читатель (`reader`) | Просмотр списка и отдельных новостей, просмотр комментариев, добавление комментариев |
| Модератор (`moderator`) | Все действия читателя, а также создание, изменение и удаление новостей и комментариев |

Проверки доступа к новостям и комментариям определены в `App\Policies\ArticlePolicy` и `App\Policies\CommentPolicy`. Политики зарегистрированы в `App\Providers\AuthServiceProvider`. Перед проверкой отдельных возможностей `Gate::before` разрешает модератору действия, которые недоступны читателю.

Для показа или скрытия элементов интерфейса используются Blade-директивы `@can`, например для ссылки создания новости и кнопок управления публикациями. Эти проверки в шаблонах дополняют, но не заменяют проверки на сервере: контроллеры и Form Request также вызывают Gate.

## Комментарии

Модель `App\Models\Comment` связана с новостью (`Article`) и автором (`User`). Таблица `comments` содержит `article_id`, `user_id`, `content` и временные метки. При удалении новости или пользователя связанные комментарии удаляются каскадно.

`CommentController` реализует добавление, изменение и удаление комментариев. При создании автором назначается текущий пользователь, а новость задаётся вложенным маршрутом. Для изменения и удаления применяются scoped route bindings, поэтому нельзя обратиться к комментарию через маршрут другой новости.

`CommentRequest` проверяет право пользователя на создание или изменение и валидирует `content`: поле обязательно, должно быть строкой и не может превышать 5000 символов. Удаление проверяется через `Gate::authorize`.

## Новости

Для статей используется resource-контроллер `ArticleController` с методами:

- `index` — список новостей, отсортированный по дате публикации и разбитый на страницы по 10 записей;
- `create` и `store` — форма и создание новости;
- `show` — просмотр новости и связанных комментариев;
- `edit` и `update` — форма и сохранение изменений;
- `destroy` — удаление новости.

Доступ к операциям контролируется `ArticlePolicy`, а `ArticleRequest` проверяет полномочия и данные:

- `title` — обязательная строка длиной до 255 символов;
- `content` — обязательная строка;
- `published_at` — необязательная корректная дата.

Модель `App\Models\Article` связана с таблицей `articles` и имеет отношение «один ко многим» с комментариями.

## Регистрация и аутентификация

Регистрация реализована в `App\Http\Controllers\AuthController`. Обязательны имя длиной до 255 символов, уникальный корректный email и пароль длиной не менее 8 символов. После регистрации пользователь получает роль читателя и перенаправляется на форму входа.

Вход выполняется стандартным сессионным guard Laravel. После успешной аутентификации идентификатор сессии обновляется. POST-маршрут входа ограничен middleware `throttle:6,1`. При выходе вызываются `logout()`, аннулирование сессии и обновление CSRF-токена.

Для защищённых маршрутов используется `auth:sanctum`. В проекте Sanctum применяется как middleware аутентификации; отдельная выдача API-токенов интерфейсом проекта не реализована.

## Модели и таблицы

- `users` — учётные записи, хеш пароля и внешний ключ `role_id`;
- `roles` — уникальное имя роли и отображаемое название;
- `articles` — заголовок, текст и необязательная дата публикации;
- `comments` — текст комментария и внешние ключи новости и автора.

Пароль автоматически хешируется cast-механизмом модели `User`:

```php
'password' => 'hashed',
```

## Тестовые данные

Команда `php artisan migrate --seed` создаёт роли, тестовые аккаунты модератора и читателя и 20 новостей. Пароли тестовых аккаунтов генерируются случайно и выводятся в консоль при запуске сидов; используйте значения из вывода команды. Seeder можно запускать повторно без создания дубликатов этих аккаунтов, ролей и демонстрационных новостей.

## Запуск проекта

Требуются PHP 8.3 или новее и Composer.

```bash
composer install
```

Создайте файл `.env` на основе `.env.example`, настройте подключение к базе данных и сгенерируйте ключ приложения:

```bash
php artisan key:generate
```

Примените миграции и заполните базу тестовыми данными:

```bash
php artisan migrate --seed
```

Запустите локальный сервер:

```bash
php artisan serve
```

Откройте адрес, указанный Artisan (обычно `http://127.0.0.1:8000`).

Для повторного создания таблиц и наполнения базы данными:

```bash
php artisan migrate:fresh --seed
```

> `migrate:fresh` удаляет все существующие таблицы в выбранной базе данных. Используйте эту команду только для локальной или тестовой базы.

## Тестирование

Запустите тесты проекта:

```bash
php artisan test
```

Feature-тесты проверяют регистрацию и вход, защиту маршрутов, CRUD новостей, права читателя и модератора, создание комментариев, валидацию и защиту вложенных маршрутов от доступа к комментариям другой новости.
